# Vivident 외부 인프라 관리 가이드

회사 공통 리소스도 먼저 관리 저장소가 있는지 확인한다. IaC가 관리하는 리소스는 해당 저장소의 절차를 따르고, 직접 관리하는 리소스는 아래 도구를 사용한다. 프로젝트 전용 리소스는 프로젝트로 연결하며, 오시즈의 AWS·Cloudflare는 [oshiz-operations](../../oshiz-operations/SKILL.md)를 읽는다.

---
## AWS

회사 공통 AWS 리소스는 AWS CLI로 관리한다. 설정된 `vivident` 프로필을 사용하고 작업 전에 계정과 대상 리전을 확인한다.

```sh
aws --profile vivident sts get-caller-identity
```

리전은 프로필 기본값 대신 대상 리소스·관리 설정에서 확인해 명령에 명시한다. 인트라넷 백업의 리전도 현재 백업 정의에서 확인한다.

---
## Cloudflare

DNS·Tunnel 등 Cloudflare 리소스는 `cf` CLI로 관리한다. `cf auth list`와 현재 도움말로 사용 가능한 프로필을 확인하고, 회사 계정·영역·대상 리소스를 대조한다. 프로필 이름만으로 소유 계정을 판단하지 않는다.

선택한 프로필·영역을 명시하고, 필요한 명령은 하위 도움말이나 `cf schema --help`로 확인한다. 클러스터에서 실행되는 커넥터와 원본 서비스 설정은 인트라넷 저장소에서 관리한다.

---
## 오브젝트 스토리지

인트라넷의 S3 버킷·객체에는 설정된 `vivident_intranet_s3:` rclone 원격을 사용한다. `rclone listremotes`로 원격을 확인하고, 로컬 원격 설정의 엔드포인트·리전·인증 방식과 요청 대상을 대조한다.

백업 버킷·접두 경로·정책은 인트라넷 저장소의 해당 ObjectStore·Longhorn 백업 설정에서 읽는다. 원격의 환경 변수 인증에 필요한 회사 AWS 인증만 해당 명령에 전달한다. AWS CLI의 프로필 선택만으로 rclone 인증도 준비되었다고 가정하지 않는다.

조회·복사·삭제는 요청한 버킷과 접두 경로로 한정하고 비공개 접근을 유지한다. 백업 설정 변경은 인트라넷 저장소로, 데이터베이스·볼륨 복원은 담당 오퍼레이터의 복구 절차로 연결한다.
