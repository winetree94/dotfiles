# 메일 서버 외부 인프라 관리 가이드

먼저 관리 저장소를 확인한다. 저장소가 관리하는 리소스는 해당 절차를 따르고, 직접 관리하는 리소스는 아래 도구를 사용한다.

## Hetzner

`hcloud --context winetree94`로 공급자 리소스를 관리한다. 같은 컨텍스트에 Tinyrack 클라우드도 있으므로 이름·ID와 현재 할당을 대조한다.

| 리소스 | 이름 / ID |
| --- | --- |
| 서버 | `mail-server` / `115401154` |
| Floating IP | `mail-server` / `147638286` |

현재 명령 도움말과 대상 서버·Floating IP 할당을 확인한 뒤 작업한다. 공급자 측 생성·삭제·할당은 `hcloud`, 호스트 OS·게스트 내부 주소는 저장소의 Ansible이 담당한다.

삭제 보호는 해제가 요청에 포함되지 않았다면 유지한다. 메일 Floating IP와 서버 기본 IP를 구분한다. PTR은 Hetzner에서 관리하며 관련 변경 후 메일 저장소의 지침·README에 따라 DNS와 메일 전달을 검증한다.

---
## Cloudflare

DNS는 `cf` CLI로 관리한다. `cf auth list`, 현재 하위 명령 도움말과 `cf schema --help`로 명령을 확인하고 계정·프로필·영역·대상을 대조한다. 선택한 프로필과 영역은 명시한다.

메일 DNS는 `winetree94.com` 영역에서 확인한다. SMTP·IMAP 등 메일 프로토콜에 Tinyrack·홈랩의 Tunnel 전용 정책이나 일반 HTTP 프록시를 적용하지 않는다. 실제 리스너·주소·TLS 설정은 메일 저장소를 따른다.

---
## 오브젝트 스토리지

버킷·객체는 `rclone`으로 관리한다. `rclone listremotes`로 `hetzner_fsn:`과 `hetzner_hel:`을 확인하고, 요청 대상의 스토리지 엔드포인트와 로컬 원격 설정을 대조해 선택한다. 서버 위치로 스토리지 리전을 추정하지 않는다.

백업 버킷·접두 경로·엔드포인트는 이 저장소의 CNPG ObjectStore·Longhorn 백업 설정에서 읽는다. Tinyrack 클라우드와 버킷을 공유하므로 조회·복사·삭제·동기화는 요청한 접두 경로로 제한한다. 클러스터 하나의 작업을 버킷 전체에 적용하지 않는다.

원격의 환경 변수 인증에 필요한 인증만 해당 명령에 전달하고 비공개 접근을 유지한다. 백업 정의 변경은 저장소에서, 데이터베이스·볼륨 복원은 담당 오퍼레이터의 절차로 수행한다. 객체 복사만으로 서비스 복구가 완료되었다고 판단하지 않는다.
