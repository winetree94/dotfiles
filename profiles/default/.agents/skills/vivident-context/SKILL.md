# Vivident 작업 컨텍스트

Vivident 관련 작업을 시작할 때 대상 저장소와 관리 정본을 먼저 확정하고, 필요한 전문 스킬과 프로젝트 지침을 함께 적용한다. 이 스킬은 공통 지침이며 프로젝트별 설정이나 운영 절차를 복제하지 않는다.

## 작업 위치와 정본 확인

1. 작업이 특정 저장소에 속한다면 그 저장소의 지침을 정본으로 삼는다. 저장소 루트부터 작업 디렉터리까지 적용되는 `AGENTS.md`와 README, 프로젝트 내부 스킬을 읽는다.
2. 작업에 필요한 저장소가 `~/Workspaces/vivident` 하위 경로에 존재하지 않는다면 체크아웃하고 진행한다.
3. 체크아웃이 오래되었을 가능성이 있으면 원격 정본을 확인하되, 사용자의 기존 변경을 덮어쓰지 않는다.

## 전문 스킬 선택

요청과 일치하는 전문 스킬이 있으면 이 스킬과 함께 사용한다.

- 오시즈 서비스 운영, 제품 작업, 배포, 고객 지원, 운영 데이터 분석은 `oshiz-operations`를 사용한다.
- Vivident 공통 인트라넷, 사무실 네트워크, CI 러너와 외부 인프라는 `vivident-infrastructure`를 사용한다.

# 작업에 필요한 환경이나 도구가 없을 때

프로젝트 의존성 설치, 가상환경 설정, 임시 실행 바이너리 다운로드처럼 사용자 권한으로 간단히 해결하고 되돌릴 수 있는 문제는 자율적으로 복구한 뒤 작업을 계속한다.
인증·권한이 필요하거나 시스템 설정을 변경해야 하거나, 정해진 도구·절차를 벗어나야 한다면 작업을 멈춘다. 이때 막힌 이유와 발생한 오류, 사용자가 해야 할 조치를 설명하고 실행을 위임한다.

# 비밀 관리(Bitwarden)

작업 진행 중 비밀 접근이 필요한 경우 `bw` cli 도구를 사용한다. 주어진 `id`를 활용해 필요한 필드만 조회한다. 비밀번호나 사용자명은 가급적 셸 변수·명령 인자로 복사하지 않고, 대상 도구가 지원하면 표준 입력으로 직접 전달한다. 비밀을 컨텍스트에 노출하지 않도록 주의한다.

Bitwarden 에 등록된 ssh 키를 사용해야 하는 경우 키를 임시 파일에 기록해 `ssh -F /dev/null -o IdentitiesOnly=yes -i <임시 키 파일> <사용자>@<사설 IP>`로 전달한다. 작업이 끝나면 임시 키 파일을 제거한다.
