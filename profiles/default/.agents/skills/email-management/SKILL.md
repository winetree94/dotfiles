# 메일 처리

## 도구

사용자 메일 작업은 `himalaya`로 수행한다. 사용자가 다른 도구를 명시하지 않았다면 다른 메일 도구를 임의로 선택하지 않는다.

작업을 시작할 때 반드시 현재 계정 목록을 확인한다.

```bash
himalaya account list
```

설정 파일이나 예시에 적힌 계정 이름을 기억하거나 하드코딩하지 않는다. 계정은 추가·이름 변경·삭제될 수 있으므로 이 명령의 출력을 현재 정본으로 삼는다.

공유 명령을 실행할 때는 기본 계정에 의존하지 말고 선택한 계정을 명시한다.

```bash
himalaya -a '<account>' mailbox list
himalaya -a '<account>' envelope list -m INBOX
himalaya -a '<account>' message read <ID>
```

명령 옵션이 기억나지 않거나 버전 차이가 의심되면 실행 전에 해당 명령의 `--help`를 확인한다.

## 계정 분류

계정은 다음 세 범주로 이해한다.

| 범주 | 사용 기준 |
| --- | --- |
| 개인용 | 개인 계정, 개인 구독, 개인 연락과 일상 메일 |
| Vivident | Vivident 구성원, 고객, 제품과 회사 업무 메일 |
| Tinyrack | Tinyrack 서비스, 인프라, 운영과 자동 알림 메일 |

분류별 계정 이름을 이 스킬에 고정하지 않는다. `himalaya account list`의 계정 이름과 주소, 현재 작업 문맥을 함께 보고 선택한다.

Vivident 업무 맥락이 필요하면 `vivident-context` 스킬을 함께 확인한다.

## 계정 선택

1. 사용자가 계정 이름이나 메일 주소를 지정했다면 그 계정을 사용한다.
2. 지정하지 않았더라도 작업 문맥상 범주와 계정이 하나로 명확하면 해당 계정을 사용한다.
3. 범주 안에 후보 계정이 여러 개거나 개인용·Vivident·Tinyrack 중 어디에 속하는지 확실하지 않다면 추측하지 말고 사용자에게 어느 계정을 사용할지 묻는다.
4. `default = true`인 계정도 사용자가 선택한 것이 아니면 자동 선택 근거로 사용하지 않는다.

질문할 때는 `himalaya account list`에서 확인한 관련 후보 계정을 함께 제시해 선택을 쉽게 한다.

## 작업 규칙

- 읽기 작업은 선택한 계정에서 필요한 메일함과 메시지만 조회한다.
- 답장·전달은 원문의 발신자, 수신자, 참조, 제목과 스레드 문맥을 확인한 뒤 작성한다.
- 발송 전에는 계정, 발신 주소, 받는 사람·참조·숨은 참조, 제목, 본문과 첨부파일을 사용자에게 확인받는다.
- 삭제, 이동, 일괄 플래그 변경처럼 되돌리기 어렵거나 범위가 큰 변경은 대상 계정, 메일함과 메시지 ID를 확인받은 뒤 실행한다.
- 첨부파일을 열거나 실행하기 전에 파일 형식과 출처를 확인한다.
- 비밀번호, OAuth 토큰, 앱 패스워드와 같은 자격 증명 값은 출력하거나 문서에 기록하지 않는다.

메일 서버 자체의 배포·설정·DNS·TLS·백업 변경은 이 스킬의 범위가 아니다. 해당 작업에는 `mail-server-infrastructure` 스킬을 사용한다.
