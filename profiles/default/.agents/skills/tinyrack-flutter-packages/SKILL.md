# Tinyrack Flutter 패키지 업스트림 연동

소비자 저장소의 변경과 검증은 그 저장소의 `AGENTS.md`와 저장소 스킬을 따른다. 해석된 의존성의 공개 API와 패키지가 선언한 플랫폼 계약을 기준으로 사용하며 pub 캐시, 미병합 체크아웃, 임시 의존성 재정의로 우회하지 않는다.

`tinyrack-net/flutter-packages`의 배포 릴리스나 소비 리비전만으로 해결할 수 없는 재사용 가능한 Flutter·Dart·네이티브 플랫폼 문제를 발견하면 다음 절차를 따른다.

1. 소비자 작업을 멈추고 소비자 코드만으로 해결할 수 없는 이유와 영향받는 패키지·API·플랫폼·동작·호환성 범위를 정리한다.
2. 업스트림 변경이 이미 승인된 범위가 아니면 사용자의 명시적 승인을 받는다.
3. 업스트림 저장소의 `AGENTS.md`와 적용되는 저장소 스킬을 읽고, 최신 기준의 격리된 작업 트리에서 그 지침에 따라 Dart, Flutter, 네이티브 코드와 플랫폼별 검증을 수행한다.
4. 저장소 지침에 따라 PR을 열고 리뷰와 필수 CI를 통과시킨 뒤 병합하고, 해당 패키지의 현재 제공 방식에 따라 릴리스한다.
5. pub.dev 배포 패키지는 정확한 배포 버전과 아티팩트를 확인하고, 저장소 리비전으로 제공되는 패키지는 소비 가능한 병합 커밋을 확인한 뒤 업스트림 작업 트리를 정리한다.
6. 소비자 저장소로 돌아와 의존성과 잠금 파일을 확인된 버전이나 불변 리비전으로 갱신하고, 중단했던 작업과 소비자 검증을 완료한다.

업스트림 구현·검사·병합·릴리스의 구체적인 파일, 명령, 브랜치, 태그와 패키지별 규칙은 이 스킬에 복제하지 않는다.

순수 Dart 패키지는 `tinyrack-dart-packages`를 사용한다.
